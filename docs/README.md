# Документация VR Control Center

VR Control Center — локальное приложение оператора OnePlace для управления Quest,
трансляциями и запуском игр на шлемах и игровом ПК.

Документы описывают реализацию в текущей ветке. Наличие функции в документации
не означает, что сборка с ней уже опубликована. Версию и commit конкретной сборки
проверяют в релизе и его CI.

| Документ                                           | Для кого и что содержит                                                       |
| -------------------------------------------------- | ----------------------------------------------------------------------------- |
| [SDD — устройство системы](SDD.md)                 | Разработчик: процессы, модули, данные, IPC, сценарии и защита от гонок        |
| [Руководство оператора](operations.md)             | Установка, подключение USB/Wi-Fi, трансляции, игры, время, диагностика        |
| [Разработка](development.md)                       | Запуск из исходников, структура проекта и правила внесения изменений          |
| [Проверки и Windows-релиз](testing-and-release.md) | Автоматические проверки, состав пакета, CI и ручная приёмка                   |
| [Известные ограничения](known-limitations.md)      | Что пока не гарантируется и что нужно доработать                              |
| [Текст Windows-релиза](releases/windows.md)        | Краткие release notes, которые workflow подставляет в черновик GitHub Release |

[Визуальный стиль UI](ui-style.md) описывает типографику, токены, иконки и движение.

## Как поддерживать документы

При изменении поведения обновляйте соответствующий сценарий и ограничения в
том же PR. Конкретные значения в SDD привязаны к исходникам; контрактами служат
`src/shared/contracts`, проверкой поведения — `tests`. Если они расходятся с
описанием, исправляйте документ после проверки реализации.

В Git храним постоянную документацию и принятые проектные решения. Разовые аудиты,
сырые логи, результаты замеров конкретного ПК и рабочие заметки можно держать в
`docs/local/`: каталог игнорируется Git. Подтверждённые актуальные выводы переносим
в SDD, ограничения и сценарии приёмки. Исторический аудит 6 ноября 2026 года
оставлен локально именно там; его исходный вариант также остаётся в истории Git.
