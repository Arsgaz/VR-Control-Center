# Известные ограничения

Этот список описывает текущую реализацию. Он не является отчётом о проверке
физической арены. Исправленные исторические дефекты не следует переносить сюда
как актуальные.

| Область               | Что реализовано                                                         | Что остаётся и почему это важно                                                                                                                           |
| --------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Идентичность шлема    | Сравнение `ro.serialno` при USB → Wi-Fi                                 | В конфигурации хранится IP, а не hardware serial. Reconnect/команды по старому IP не распознают другой авторизованный шлем, получивший этот адрес         |
| Смена IP              | Ручная правка адреса либо новая USB-настройка                           | Автопоиска нового IP и объединения карточек по serial нет                                                                                                 |
| USB-подключение       | Общая блокировка USB-настройки, точный USB serial, ограниченные повторы | Не входит в очередь существующей карточки; параллельный disconnect/reconnect может помешать настройке. Карточка сохраняется отдельным IPC после настройки |
| Android-запуск        | Свежий discovery, проверка адреса, блокировка запуска на шлем           | Нет общего поколения/очереди с disconnect. Отправленная команда может выполниться уже после смены намерения оператора                                     |
| Видео                 | Сессия scrcpy на карточку, адресный запуск и ожидание stop→start        | `running` подтверждает процесс, не первый кадр. Нет автостарта трансляции после восстановления Wi-Fi                                                      |
| Выход                 | Таймеры runtime прекращаются, scrcpy получает kill                      | Нет общего ожидания `close` всех дочерних процессов при выходе                                                                                            |
| Несколько экземпляров | Очередь записи в одном main                                             | Межпроцессной блокировки конфигурации и эксклюзивного владения ADB нет                                                                                    |
| Фоновый режим         | Более редкая телеметрия и лимит её параллельности                       | IPC событий скрытому окну сохраняется; активные трансляции продолжают потреблять ресурсы                                                                  |
| Память                | Ограничен LRU кэш метаданных                                            | Не ограничена вся память Electron, общий дисковый кэш и объём stdout/stderr короткой команды                                                              |
| Время Quest           | Отправка времени ПК и чтение результата                                 | Private Binder API может отличаться/быть запрещён прошивкой. Ошибка проверки не откатывает изменение                                                      |
| Игры на ПК            | ОС открывает проверенный путь; есть защита от быстрого повтора          | Нет определения готовности сервера, слежения за процессом и управления его завершением                                                                    |
| Настройки             | Отдельная неброская кнопка                                              | Нет пароля/ролей; оператор с доступом к приложению может менять настройки                                                                                 |
| Распространение       | Проверяемый фиксированный Windows x64 комплект                          | Нет цифровой подписи и автоматического обновления. Драйверы/разрешения и сеть подготавливаются отдельно                                                   |
| Автозапуск            | Поле `launchAtStartup` хранится в схеме                                 | Интеграция с автозагрузкой ОС не реализована                                                                                                              |
| Платформы             | Windows x64 package и macOS-разработка                                  | Linux и другие архитектуры не являются проверенной поставкой                                                                                              |

Собственные PNG игр на ПК хранятся в `userData/team-game-icons`. Автоочистки
неиспользуемых копий после отмены редактора, смены картинки или удаления игры пока
нет. Системное извлечение иконки зависит от ОС и типа ярлыка; если ОС отдаёт
стандартную иконку, можно назначить собственную PNG.

Steam-импорт зависит от доступности публичных metadata магазина: неизвестные игры
без кэша не классифицируются наугад. Есть ограничение времени scan; для большой
первой библиотеки может понадобиться несколько обновлений. Импорт не удаляет
неустановленные карточки и не поддерживает список скрытых AppID. Подготовка SteamVR
реализована для Windows x64 и требует установленного runtime. Проверяется соединение
OpenVR, не tracking/compositor/первый кадр и не режим запуска самой игры. Нативную
цепочку с реальным SteamVR, Air Link/Steam Link/Virtual Desktop нужно проверить
на целевом ПК; mock-тесты её не заменяют. Steam-кэш пока без общего дискового лимита.

## Что проверять перед расширением эксплуатации

Сначала подтвердить адресную работу нескольких физических шлемов, USB на целевом
Windows-ПК, поведение при перезапуске/Wi-Fi loss и остановку процессов на выходе.
Далее закрывать постоянную аппаратную идентификацию и общую координацию всех
действий на шлеме. Более строгие гарантии нельзя выводить только из UI-lock.

Для PC VR пока не измерены CPU, GPU, RSS/private memory и влияние на frame time.
План измерения: одна и та же игра и сцена, без VR Control Center и с ним; затем
0/1/8 шлемов, видимое окно/трей, без трансляций/с одной/с несколькими, библиотека
до/после загрузки. Учитывать всё дерево Electron, ADB и scrcpy, собирать одинаковые
интервалы нагрузки и p95 времени появления изображения. Снижение количества
ADB-команд не является результатом такого измерения.

Сырые замеры и параметры конкретного ПК можно хранить локально в `docs/local/`;
в репозиторий переносить воспроизводимый сценарий и обезличенные выводы.
Сценарии приёмки — в [testing-and-release.md](testing-and-release.md).
